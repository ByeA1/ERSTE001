# 协作约定与决策记录

## 参与方

- 用户（Saki）：目标、偏好、最终决定权。
- GPT（Codex 会话）：设计评审、技术审查，给出原理与修复方案。
- VVA：实现、本地执行、测试、部署、与 GPT 交换意见。

## 工作方式

1. 同一问题最多两轮讨论、两轮评审，第三轮必须决策或做原型验证。
2. 分歧用数据或实验解决，不用形容词。
3. 每轮交换固定格式：
   - VVA → GPT：变更摘要（≤5 行）、预览链接、关键截图、指标（首屏体积 / GLB 大小 / 构建结果）、未决问题（≤3）。
   - GPT → VVA：`R1..Rn`，每条带严重度（blocker / suggestion / nit）与修复后的预期行为。
   - VVA 回复：逐条「采纳 / 部分采纳 / 不采纳 + 依据」。

## 分支与发布

- `main`：线上分支，只放已验证的提交。
- 功能分支：`feat/…`、`chore/…`，合并前需在本地跑通预览。
- 部署：推送 `main` 即触发 Pages 构建；回滚用 revert 或强制指回已知良好提交。
- 同一提交只部署一次，不叠加修改；部署失败先回滚再排查。

## 决策记录

### ADR-001 以远端 `main` 作为唯一基线（2026-11-04）

- 背景：本地仓库与远端是两条无关历史，本地有未提交改动，远端才是线上版本。
- 决定：`main` 重建为跟踪 `origin/main`；本地改动冻结在 `archive/local-20260916`，另存文件快照。
- 理由：线上即事实。任何迁移都必须从可部署的那一版出发，否则无法验证。
- 影响：本地历史提交不再作为主线；若日后需要，可从 archive 分支取回。

### ADR-002 行尾统一为 LF（2026-11-04）

- 背景：`index.html`、`style.css` 的“巨大差异”经核查全部来自 CRLF/LF 混用。
- 决定：`.gitattributes` 设 `text=auto eol=lf`，仓库配置 `core.autocrlf=false`。
- 理由：消除噪声 diff，让真正的改动可读。

### ADR-003 图片资产规格（2026-11-04，来自 GPT 评审 R3）

- 决定：AVIF 主格式、WebP 回退，宽度梯度 480 / 960 / 1440 / 1920，单张上限 50 / 100 / 180 / 280 KB，配 `srcset` / `sizes`，不放大原图。
- 状态：待实施。

### ADR-004 双份 HTML 的处理（2026-11-04，来自 GPT 评审 R2）

- 决定：先冻结副本作为迁移基线，禁止继续双份修改；随后抽公共模板与单一内容源，逐页迁移并保留原 URL。
- 状态：冻结已完成（archive 分支），迁移待做。
