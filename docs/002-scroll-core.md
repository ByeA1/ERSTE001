# ERSTE002 章节演出与导演工作流

ERSTE002 采用无底壳 Rev 3 模型。四章共 11 个讲解镜头。底部「上一镜 / 下一镜」和键盘左右方向键沿同一时间轴切换，每个镜头停在对应文案完整显示的位置。右侧章节导航直达各章首个讲解镜头。最后一镜提供「回到开头」，重新播放开场揭示。开启减少动态效果时，按相同顺序直接切换静帧。

按前后镜头键时，当前文案随镜头运动淡出。下一段文案可以在运镜和布光期间进场，到观察机位后完整停留。模型标记在到达对应机位后显示，演出编辑器拖动进度时也可预览文案和标记。

1. 外观。暗处先见红色轮廓，再由白色扫光揭出键盖和上盖。相机缓慢推进后停留。
2. 右手人体工学。食指和中指、上盖肩部、掌心分别使用同一前后位置上的左右表面点。三个观察位置沿外壳依次向后移动。
3. 结构与装配。先从下方看开放底部，再确定爆炸构图并展开五组部件。完整爆炸位保持静止。
4. 结构强化。侧面剖切后推进到类工字形截面，镜头与切面稳定时由低角度聚光扫过。退刀后从开放底部看筋板、侧壁和横撑。键盖独立提取并翻转，先以宽光束交代全貌，再用聚光照交叉筋。末镜按壳体与电子件、滚轮、键盖的顺序归位，然后拉远并恢复红色轮廓光。

## 本地预览

在仓库根目录运行 `npm run dev -- --port 5197`。

- 正常页面：[ERSTE002](http://127.0.0.1:5197/cases/erste002/index.html)。
- 手动编辑：[演出编辑器](http://127.0.0.1:5197/cases/erste002/index.html?editor=1)。它只在回环地址提供，打开后可拖进度、调参、保存当前镜头、保存本机草稿或导出 JSON。
- 如果浏览器里有旧缓存，先直接打开上面的开发服务器地址。线上页面和开发分支是不同版本。

在「自由查看」里可以拖动装配滑杆、绕转镜头，或选中零件后提取、翻转、仅看该件。点「归位部件」回到进入自由查看时该件所在的装配位置。返回演出会恢复原章轨道，编辑器也能逐件调节位移与旋转。

## 用对话导演

可以直接对 Codex 说：

> 在 `structural-reinforcement` 的 `rib-to-wall-junction` 镜头放慢推进，保留剖面和现有横撑机位，聚光稍往螺柱移动，其他章节保持原样。

Codex 用 `node scripts/direct-002.mjs list` 定位片段和镜头，在 `story.json` 读取该段当前值，生成仅包含目标片段变更的补丁，再运行 `node scripts/direct-002.mjs apply <patch.json>`。改完重新打开本地页面，或在编辑器拖到该段机位检查。页面本身只读演出数据。

- `poses` 是命名机位，可共享。每段的 `from` 和 `to` 引用共享边界，前一段出口等于后一段入口。
- `segments[].id` 是稳定的对话标识。`duration` 是该段完整区间的基准秒数，`hold` 是观众停留的段内进度。`shots[].at`、`beats[].start/end`、镜头提示的 `cue.start/end` 均使用段内 0–1。剪辑片段长度会改变整条时间轴的百分比，其他片段的局部镜头和时长保留。
- `shots` 可继承 `pose`，也可覆盖任一镜头通道，例如 `camera.target` 或 `lights.focus.angle`。只为一段改机位时，优先在该段镜头中覆盖通道。改共享边界会涉及两侧片段。
- `beats` 存放两种语言的标题与正文，顺序为中文、英文。每段文字区间必须连续覆盖 0–1。`reveal` 控制入场起点，介于 `start` 和 `arrive` 之间。`arrive` 指定观察机位与模型标记的起点，未填 `reveal` 时也作为文案入场点。`leave` 可提前结束文案。`tag` 用于场记。
- 世界空间中 X+ 为拇指侧，Y+ 为上方，Z+ 为前端。模型最长轴归一到 0.3 个世界单位。`camera` 与聚光灯的 position/target 均用该坐标系，FOV、灯角和剖切旋转使用度数。camera.frame 控制桌面构图偏移，双语文字可通过 beat.layout 切换到左侧、右侧或下方。
- `cut.position` 是切面上一点，`cut.rotation` 是把默认 +Z 法线按 XYZ 旋转后的朝向。保留法线正侧。侧剖从模型 X+ 一侧向内推进。局部类工字形近景取自 X = 0.015 的实际切片。
- `lighting` 可指定 Studio、Ergonomics、Assembly 或 Structural。每个预设共享主光、补光、轮廓光和聚光灯，可在机位覆写各盏灯的参数。位置、光强、光色和角度随时间轴插值。两次提示闪烁结束后，由真实聚光灯完成结构讲解。
- `explode` 控制五组部件沿装配轴展开。`assembly.<part>.offset` 与 `rotation` 是叠加在爆炸位上的世界坐标位移与绕部件中心的 XYZ 旋转，`isolate` 可单独显示某组。零位移、零旋转加 `explode: 0` 恢复模型的原装配变换。

补丁格式示例仅改一个片段的时长和停留点。修改机位时，`set.shots` 应包含该片段完整的镜头数组，原样带上其中未改的镜头。

```json
{"segment":"right-hand-ergonomics","set":{"duration":10.4,"hold":0.75}}
```

要在两段之间增加镜头片段，使用 `{"after":"已有段 ID","insert":{…新片段…}}`。新段的入口和出口均引用原交界机位，在段内安排自己的镜头。也可在末尾追加，以前段出口为新段入口。

### 锁定与回滚

- `node scripts/direct-002.mjs lock structural-reinforcement` 锁定片段。日常补丁、编辑器保存和导出应用都会保护该段的内容及共享机位。要改它时先 `unlock`。
- `node scripts/direct-002.mjs check` 校验当前文件，可加文件名检查导出草稿。用 `replace <draft.json>` 应用分段版导出，应用时仍检查锁定。旧版平铺轨道可以作为编辑器本机预览导入。
- `backup` 存快照，`history` 列出修订，`undo` 撤销匹配当前文件的最近修改，`restore <修订 ID> before|after` 明确恢复某一版本。每次改动均保存前后快照，路径为 `.audit/002-director/history`。恢复整个修订也恢复该版本的锁状态。Git 开发分支保留长期版本。
- 编辑器里的进度是整条演出的 0–1。共享边界和锁定片段无法通过「保存关键帧」覆盖。保存后可导出，再用导演脚本把草稿应用到分支。

## 模型和剖切

使用 Rev 3 封闭 GLB。用户提供的 `ERSTE002_exploded_website_rev3_closed.glb` 与仓库 `assets/shell-full.glb` SHA-256 相同，开头为 `a7c8796c`。按索引验证，上盖 202,074 三角形、按键盖 91,118 三角形，各自闭合、绕向一致且有正的有向体积。加强筋和横撑属于上盖几何。装配中的电子件是参考件，约 33 g 是设计目标。

Three.js 本地裁切与实际的截面三角网格一起工作。运行时从闭合 GLB 的三角形与切面求交，沿共享边接出闭合轮廓，再对材料区域三角化。轮廓内部的孔洞与空气保留。实体切面以同一组材质和真实聚光灯渲染。上盖与键盖的显示网格使用按角度加权的法线，并在硬边处拆分法线，剖切继续使用原始闭合网格。模型沿用黑红紫配色。开场、人体工学侧视与装配展开使用红色轮廓光，结构聚焦使用中性光。

渲染只在镜头播放、自由查看变化、编辑或视口变化时提交。停留章节、隐藏或终端关闭案例时停止，恢复时从原机位续播。移动端限制绘制分辨率，保留几何精度。WebGL 或模型载入失败时，仍可看静态封面和逐章文字，并可重新载入。

视觉升级以 `7ca8195` 为回滚基线。第 01 镜使用独立产品主视觉，第 02 镜以模型表面点投影绘制高低参照线，第 08 镜用斜向剖面构图与红白分光，第 10 镜用掠射光及浅红边光呈现内侧筋位。四章沿用同一黑红基底，分别通过产品标题、工程图注、装配铭牌与剖面版式区分。对照图位于 `.audit/002-visual/comparison-desktop.png`。

工作室环境在载入时烘成一张 PMREM 贴图。`lightingTrack[].reflection` 存储 `intensity` 和 `yaw`，分别控制灯棚反射量和水平方向。编辑器「环境与剖切」中的灯棚参数可随灯光帧独立保存。直接聚光、半球补光和环境反射各自控制。模型保持原始底色和几何，塑料使用零金属度和固定粗糙度。场景使用 ACES 映射、单张软阴影图和按需渲染。帧时间、双语文案和两次提示闪烁定义沿用基线。

摄影棚版本以 `85376db` 为同机位对照基线。浏览器转动参考演示时可见亮带沿耳罩移动，织物保持暗哑。案例说明描述了非对称灯棚，公开代码确认了 PMREM、ORM、清漆材质和独立直射灯。ERSTE002 采用带渐变边缘的非对称条形反光板，每次加载只生成一次 128 像素面长的 PMREM。当前 GLB 缺少 UV 和 AO 贴图，本轮通过遮挡阴影、低强度补光和掠射聚光呈现局部厚度。对照图位于 `.audit/002-studio/comparison-desktop.png`。[案例说明](https://www.dopaminestudio.io/project/3d-product-visualization) · [在线演示](https://alessandrocofone.github.io/aripods-picker/airpods/index_finale.html) · [公开代码](https://github.com/alessandrocofone/aripods-picker/blob/main/airpods/index_finale.html)

## 独立灯光轨道框架

每章的 `lightingTrack` 使用段内 0–1 进度，首尾必须包含 0 和 1，相邻章的出口与入口灯光一致。每帧保存 `at`、`ambient` 和 `lights`。四盏灯各自包含 `position`、`target`、`intensity`、`color`、`angle`，沿统一播放头独立于相机插值。四套命名预设仍可作为起点。已有四章灯光数据作为初始演出配置，后续可以逐段调整。

`shots`、`lightingTrack` 和 `beats[].reveal` 共用时间轴，可安排镜头、灯光和文案同时运动。复制某个灯光帧到更晚进度可形成稳定观察区间。反向播放使用同一数据，章节停留时停止渲染。

编辑器支持「仅保存灯光」和「删除灯光帧」，关键帧列表包含灯光时间点。仅保存灯光不会插入相机或零件关键帧。保存本机草稿、导入导出、片段锁定与导演脚本备份回滚继续可用。对话修改可通过 `direct-002.mjs apply` 的 `set.lightingTrack` 更新指定片段的完整灯光数组。

渲染沿用 ACES 色调映射与固定黑红紫材质颜色，塑料粗糙度调整至 0.62。降低演出中的半球补光，主光与结构聚光按当前揭示目标交接阴影投射，单帧只启用一张 1024 阴影图，使用 PCF 软边过滤。实体封口参与投影和接收阴影。

本轮按整体框架交付。34 项自动测试和生产构建通过，覆盖独立灯光插值、停留、锁定、保存删除和旧格式兼容。桌面 Chrome 验证了镜头静止时画布光影变化，以及单独保存、导出、删除灯光帧后镜头轨道保持原样。

Windows 桌面 Chrome 完整正放和倒放第四章。正放约 38.2 秒，4,471 次绘制状态采样的间隔 P95 为 9.1 ms。两组提示各闪两次，正放复原整机，倒放回到第三章的完整爆炸状态。390 × 664 手机模拟视口通过触控自由装配和减少动态效果下的实体剖面检查。Safari 真机表现待验证。
