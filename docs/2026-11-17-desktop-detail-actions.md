# 档案详情：仅手机互换操作位置

## 修正

前一轮把进入项目与装置检视的位置互换应用到了全部视口，本次按用户反馈限定为手机布局。

- PC：档案盒预览旁为“360° 查看档案装置”，简介下方为“进入项目”与收藏；进入项目恢复占据正文操作行的主要宽度。
- 手机：保留预览旁“进入项目”、正文下方“查看档案装置”与收藏的位置。
- 使用同一组实际按钮，在布局变化时移动节点，不复制控件或重绑监听器。中英文刷新、项目切换和调整窗口后保持正确位置。
- 紧凑的 PC 窗口（1000×760、804×1000，无触屏）也保留 PC 操作顺序；窄屏手机与紧凑触屏布局使用手机顺序。
- PC 档案详情主要按钮的茶色底从 73% 不透明度减轻至 64%，使用较亮的暖白字；背景模糊为 10px。保留对角细线与独立箭头分区。手机茶色参数、项目页导航和项目自身配色未改动。

## 文件与验证

实现：`src/main.ts`、`src/project-showcase.css`、`src/action-buttons.css`。

扩展 `scripts/check-mobile-case-layout.mjs`：校验不同端的顺序、两个按钮唯一性、跨断点缩放后节点身份不变；实际点击两款项目入口、检视、关闭与返回，检查中英文、章节往返和主图像素。

Edge 浏览器 1440×900 PC、390×740 触屏模拟通过，另在页面运行中往返检查 1000×760、804×1000、390×740、1440×900 的操作位置。PC 两款项目按钮的实际截图合成检查均通过：在按钮下方临时切换黑/白背景，空白槽位亮度变化约 89.8/255，确认背景确实透过按钮，而非仅声明半透明 CSS。该探针在测试后恢复，不写入产品界面。

`npm run build` 通过，版本 `a48c43e30f9916d0`。开场时间线 10 项、目录 3 项、项目展示 5 项、公共项目默认能力 3 项与 Logo 用法检查通过。

Logo 整合审计仍有既存的保护模型哈希差异：当前模型 `94fc471418156825…`，规则期待 `dda42b9b3b471d11…`。本轮未修改模型或该审计规则。构建仍提示既有较大资源包。
