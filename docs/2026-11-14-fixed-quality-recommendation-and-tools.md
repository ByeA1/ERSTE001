# 启动前推荐固定预设、详情清晰度与手机工具组 · 2026-11-14

> 2026-11-15：下文三帧固定机位检测已被[真实浏览负载逐档检测](./2026-11-15-startup-quality-probe.md)取代。手动选择锁定规则保持；手机工具组底衬已在[透明控件整理](./2026-11-15-cassette-switch-and-commands.md)中取消。

本次决定覆盖同日早先的「自动 / 流畅优先」方案：**帮助用户在开场前选定预设，不做运行中的动态画质调节。**

## 最终行为

1. 初次加载在资源准备阶段完成三帧固定档案海机位的 CPU 更新及 GPU 完成计时，再确定一个推荐档位。记录为提示性启动检测，不宣称等价于拖动 FPS。检测完成后才启动原有开场时间轴。
2. 设置显示「系统推荐 · 档位」和预设卡片上的推荐标记；该按钮只应用本次检测得到的固定预设，没有自动模式开关。
3. 用户点击四个预设或修改自定义参数后，记录 `qualityOrigin=user`，始终保持选择；浏览、帧率变化、打开项目、刷新及开场重播都不会替用户换档。刷新仍会算出推荐结果供查看，但不覆盖用户配置。
4. `qualityOrigin=system` 时，每次页面启动可重新做一次推荐。运行期间不再采集帧率作为换档依据。002 内部的第二套自动调节也已移除，继承宿主固定档位。
5. 唯一场景例外：系统推荐配置进入单个档案盒详情，效果临时升一级（完整档封顶），并把封面渲染比例保持 100%、DPR 上限至少采用本套详情配置的 1.5×。返回档案海恢复原预设；不覆盖保存的基础档和自定义参数。**手动预设不参与临时升级。**
6. 需要的基础档与详情档着色器在开场前预热，避免第一次进入详情时临时集中编译。原开场轨迹和 002 四章 11 镜没有重新设计。

固定预设字段仍由 `src/adaptive-quality.ts` 中的渲染映射提供；旧采样类保留给历史对照测试，终端及 002 当前运行路径不再使用它。新策略在 `src/quality-recommendation.ts`。偏好版本升为 3，旧 auto 迁移为系统推荐，已有手动档及自定义参数保留。

## 用户提供的设备反馈

- 用户反馈：苹果 18 Pro 上旧逻辑在滑动档案海时降到流畅，但手动完整也很流畅。
- 用户反馈：4060 笔记本 Edge 需要流畅档才能保持流畅。
- 以上是用户实测记录，不是本机重复测得的结果。本次移除了以滑动帧间隔持续降档的路径，避免把输入调度抖动直接当成画质不足；没有按手机名称一律降级，也没有硬编码所有 4060 必须使用某档。
- 推荐基于有限的启动场景；驱动、供电、温度、浏览器、实际输入和背景程序仍会影响体验。推荐不等于上述两台目标设备已经通过实机验收。用户的手动选择拥有优先权。
